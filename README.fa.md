# نصب Element روی VPS

[English README](README.md)

این پروژه یک نصب‌کنندهٔ مستقل برای **Element Server Suite Community** است. پیام‌رسان، سرور Matrix، سرویس احراز هویت، تماس صوتی و تصویری و پایگاه داده از پروژهٔ رسمی Element می‌آیند. نصب‌کننده فایل‌ها را از بخش Releases همین مخزن دریافت می‌کند تا VPS بتواند بدون دسترسی مستقیم به رجیستری‌های کانتینر، سرویس را راه‌اندازی کند. [پروژهٔ رسمی](https://github.com/element-hq/ess-helm)

## آماده‌سازی سرور

یک VPS اختصاصی و تازه با Debian 12 یا Ubuntu 22.04 یا نسخه‌های جدیدتر، systemd، پایتون ۳، curl و دسترسی root یا sudo لازم دارید. بستهٔ پیش‌فرض برای پردازنده‌های amd64 است. حداقل منابع اعلام‌شده ۲ هسته و ۲ گیگابایت رم است. برای دانلود و بازکردن ایمیج‌ها، رشد دیتابیس، فایل‌های کاربران و پشتیبان فضای کافی در نظر بگیرید.

نام دامنهٔ اصلی بخشی از شناسهٔ دائمی کاربران می‌شود، مثلاً `@ali:example.org`. تغییر آن بعد از نصب به ساخت مجدد سرور نیاز دارد. هر شش نام زیر باید در DNS عمومی به VPS برسند. اگر IPv6 روی سرور قابل دسترس نیست، رکورد AAAA نسازید. می‌توانید نام‌های پیشنهادی را هنگام نصب عوض کنید.

| نمونه | کاربرد |
| --- | --- |
| `example.org` | دامنهٔ شناسهٔ کاربران و کشف سرویس |
| `matrix.example.org` | سرور Synapse |
| `account.example.org` | ورود و ثبت‌نام کاربران |
| `mrtc.example.org` | تماس‌های MatrixRTC |
| `chat.example.org` | نسخهٔ وب Element |
| `admin.example.org` | پنل مدیریت |

در فایروال دیتاسنتر و سیستم‌عامل، پورت‌های ورودی **TCP 80 و 443** برای وب و صدور گواهی و **TCP 30001 و UDP 30002** برای تماس‌ها را باز کنید. دسترسی SSH را حفظ کنید. سرور باید به GitHub، دامنه‌های دانلود فایل‌های Release و Let's Encrypt دسترسی داشته باشد. نصب بسته‌های سیستمیِ موجودنبود‌ه ممکن است به مخزن توزیع لینوکس نیاز داشته باشد.

## نصب با یک دستور

در نشست SSH تعاملی روی VPS اجرا کنید.

```sh
(f=$(mktemp) && trap 'rm -f "$f"' EXIT && curl -fsSL https://raw.githubusercontent.com/Sownix21/Element-Install/main/element -o "$f" && /usr/bin/python3 -I "$f" install)
```

دامنه‌ها و ایمیل تماس برای Let's Encrypt را وارد و IPهای نمایش‌داده‌شده را بررسی کنید. نصب‌کننده صحت فایل‌ها را با SHA-256 می‌سنجد، K3s، Helm، cert-manager و چارت رسمی را نصب می‌کند و دسترسی HTTPS را می‌آزماید. سرویس `k3s.service` هنگام بوت اجرا می‌شود. در پایان می‌توانید نخستین کاربر را بسازید. در ابزار MAS گزینهٔ **Set a password** را انتخاب و ایجاد حساب را تکمیل کنید. سپس از آدرس وب چاپ‌شده وارد شوید و تماس را بین دو شبکهٔ متفاوت آزمایش کنید.

## مدیریت

در هر مسیری از ترمینال دستور `element` منوی شماره‌دار را باز می‌کند. دستورهای زیر مستقیم هم اجرا می‌شوند.

| دستور | کاربرد |
| --- | --- |
| `element status` | مشاهدهٔ وضعیت سرویس‌ها، فضای ذخیره‌سازی و گواهی‌ها |
| `element start`، `element stop`، `element restart` | راه‌اندازی، توقف یا راه‌اندازی مجدد پیام‌رسان با حفظ اطلاعات و تعداد نمونه‌های هر سرویس |
| `element update` | بررسی نسخهٔ جدید ESS در آینهٔ GitHub و ارتقا پس از تأیید، با حفظ تنظیمات Helm |
| `element logs` | انتخاب پاد و مشاهدهٔ لاگ‌های اخیر |
| `element diagnose` | بررسی DNS، فضای دیسک، رم، K3s، گواهی‌ها و رخدادها. اگر K3s متوقف باشد یا دریافت ایمیج خطا بدهد، در ترمینال تعاملی پیشنهاد تعمیر می‌دهد. |
| `element verify` | بررسی گواهی‌ها، کشف سرور، API کلاینت و دسترسی به Element Web |
| `element registration` | با `enable` ثبت‌نام عمومی با تأیید ایمیل را باز و با `disable` آن را می‌بندید. می‌توانید SMTP موجود را انتخاب کنید یا مشخصات سرویس ایمیل را وارد کنید. |
| `element upload-limit` | تعیین حداکثر حجم فایل برحسب MiB. اگر پراکسی جداگانه دارید، محدودیت آن را هم بررسی کنید. |
| `element create-user` و `element users` | ساخت حساب و دیدن فهرست حساب‌های محلی و زمان قفل یا غیرفعال‌شدن آن‌ها |
| `element deactivate-user` | غیرفعال‌کردن حساب پس از تأیید مجدد نام کاربر. ممکن است کاربر از اتاق‌ها خارج شود. |
| `element reset-password` | تعیین رمز جدید با توکن مدیریت MAS. توکن و رمز هنگام ورود نمایش داده نمی‌شوند. |
| `element backup` | تهیهٔ نسخهٔ پشتیبان از دیتابیس، فایل‌ها، تنظیمات و کلیدها با توقف موقت سرویس |
| `element uninstall` | حذف کل کلاستر اختصاصی K3s، حساب‌ها، پیام‌ها، رسانه‌ها، کش و پشتیبان‌های محلی پس از واردکردن عبارت تأیید حاوی دامنه |

برای بازنشانی رمز، با حساب مدیر و دسترسی `urn:mas:admin` یک توکن کوتاه‌عمر بگیرید. برای خواندن تاریخچهٔ رمزگذاری‌شده، کاربر همچنان به کلید بازیابی یا دستگاه تأییدشدهٔ خود نیاز دارد. پس از فعال‌کردن ثبت‌نام عمومی، دریافت ایمیل تأیید را با یک حساب تازه امتحان کنید. [راهنمای دریافت توکن MAS](https://element-hq.github.io/matrix-authentication-service/topics/access-token.html)

## به‌روزرسانی فایل‌های آینه

GitHub Actions روی شاخهٔ پیش‌فرض هر روز ساعت **۰۳:۱۷ UTC** نسخه‌های رسمی را بررسی می‌کند. اگر نسخه‌ای عوض شده باشد، فایل‌ها و ایمیج‌ها را روی رانر GitHub دریافت می‌کند و پس از تکمیل بارگذاری، یک Release منتشر می‌کند. برای اجرای دستی به **Actions → Build install bundle → Run workflow** بروید. گردش کار به مجوز نوشتن در مخزن نیاز دارد. برای ساخت بستهٔ ARM، مقدار `arm64` را به `ARCHES` اضافه کنید. ارتقای VPS جداگانه و با `element update` انجام می‌شود. برای به‌روزرسانی خود منو، دستور نصب یک‌خطی را دوباره اجرا کنید. [فایل‌های منتشرشده](https://github.com/Sownix21/Element-Install/releases)

## پشتیبان‌گیری و بازیابی

پشتیبان در `/var/backups/element-install/` به‌صورت آرشیو **بدون رمزگذاری و با دسترسی محدود به root** ذخیره می‌شود. حین کپی، پیام‌رسان و تماس‌ها متوقف‌اند و در پایان به وضعیت پیشین برمی‌گردند. اگر برق سرور حین پشتیبان‌گیری قطع شد، برای بازگرداندن سرویسی که قبلاً فعال بود `element start` را اجرا کنید. پیش از حذف نصب، آرشیو را به محل امن دیگری منتقل کنید. حذف نصب پشتیبان‌های این مسیر را هم پاک می‌کند.

این آرشیو برای PostgreSQL داخلی و فضای محلی K3s ساخته می‌شود. فایل‌های هر دیسک در `volumes/<claim>` قرار دارند. تنظیمات نصب، مقادیر Helm، تعداد نمونه‌ها، Secretها و ConfigMapها هم ذخیره می‌شوند. بازیابی دستی است. روی سروری جدا با همان دامنه، نسخهٔ چارت و نسخهٔ اصلی PostgreSQL، کلیدهای تولیدشده، اطلاعات SMTP و نشانگرهای استقرار را بازیابی و دیسک‌های متناظر را بسازید. وقتی همهٔ سرویس‌های ESS متوقف‌اند، محتویات هر دیسک را با حفظ مالکیت عددی و مجوزها در مسیر دیسک متناظر برگردانید. سپس تنظیمات ذخیره‌شده را اعمال کنید و پیش از تغییر DNS، ورود، فایل‌ها و تماس را آزمایش کنید. [نگهداری و بازیابی در مستندات Element](https://github.com/element-hq/ess-helm/blob/main/docs/maintenance.md)

## رفع خطا

- اگر نصب نیمه‌کاره ماند، `element diagnose` را اجرا کنید. پس از اصلاح مشکل، `element install` نصب را با تنظیمات ذخیره‌شده ادامه می‌دهد.
- هنگام خطای گواهی، رکوردهای A و AAAA، پورت ۸۰ و وضعیت چالش‌ها را با `sudo k3s kubectl -n ess get challenges,orders,certificates` بررسی کنید.
- برای بررسی خطای یک پاد از `sudo k3s kubectl -n ess describe pod POD_NAME` استفاده کنید. پس از ارتقای ناموفق، تاریخچهٔ Helm را در خروجی عیب‌یابی ببینید. پیش از ارتقای مجدد از داده‌ها پشتیبان بگیرید.
